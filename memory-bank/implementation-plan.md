# 구현 계획

설계 기준은 [architecture.md](architecture.md)에, 진행 상태와 검증 결과는 [progress.md](progress.md)에 기록한다.

## 1. 프로젝트와 Supabase 구성

- [ ] Next.js 14 App Router, TypeScript, Tailwind CSS 프로젝트를 구성하고 `/`와 `/board`의 기본 경로를 만든다.
- [ ] Supabase 클라이언트를 브라우저용과 서버용으로 나누고 `.env.example`에 프로젝트 URL, 공개 키, 서버 전용 키 이름을 기록한다.
- [ ] SQL 마이그레이션으로 `entries`, `comments`, 외래 키, 조회 인덱스, RLS 정책, 이미지 버킷 및 권한, `supabase_realtime` publication을 구성한다.
- [ ] 마이그레이션 적용 후 공개 조회, 브라우저의 직접 쓰기 차단, 서버에서의 등록을 확인한다.

## 2. 작성 화면과 저장

- [ ] 사진 첨부·미리보기, 닉네임·메시지 입력, 마우스·터치 캔버스를 만든다. 색상, 지우개, 실행 취소, 빈 캔버스 판별, PNG 내보내기를 구현한다.
- [ ] 서버에서 입력을 검증하고 Storage 업로드 후 방명록을 등록한다. 부분 실패 시 정리하고, 중복 제출과 재시도를 처리한다.
- [ ] 성공하면 `/board`로 이동해 새 카드를 강조한다. 실패하면 입력과 그림을 보존하고 한국어 안내와 재시도 동작을 제공한다.

## 3. 보드와 상세 창

- [ ] 최신순 포스트잇 카드에 썸네일, 메시지, 닉네임, 댓글 수를 표시한다. 모바일 레이아웃과 작성 화면으로 돌아가는 버튼을 만든다.
- [ ] 상세 창에서 원본 이미지, 글, 작성 시각, 댓글 목록을 표시한다. 닉네임과 댓글을 검증하고 저장하는 서버 경로를 연결한다.
- [ ] 초기 로딩, 빈 보드, 데이터 조회 실패와 제출 실패 상태를 표시한다.

## 4. 실시간 동기화

- [ ] `entries`의 `INSERT`와 `UPDATE`를 구독해 카드 추가와 이미지 교체를 반영한다.
- [ ] `comments`의 `INSERT`로 보드의 해당 카드 댓글 수를 갱신한다. 상세 창은 현재 글의 댓글만 구독한다.
- [ ] 구독 시작과 재연결 시 최신 목록을 조회한다. 중복 이벤트, 조회와 이벤트의 시간 차이, 상세 이동과 화면 이탈 시 구독 해제를 처리한다.

## 5. 검증과 제공물

- [ ] 서로 다른 브라우저 세션 A와 B를 사용한다. A에서 사진을 등록하면 B에, B에서 손그림을 등록하면 A에 카드가 새로고침 없이 나타나는지 확인한다.
- [ ] A와 B에서 같은 포스트잇을 연다. A가 댓글을 달면 B의 상세 댓글과 카드 댓글 수가 새로고침 없이 갱신되는지 확인한다. 상세를 닫은 보드에서도 댓글 수가 갱신되는지 확인한다.
- [ ] 운영자가 새 경로에 교체 이미지를 업로드한 뒤 `image_path`를 변경한다. 두 세션의 상세 이미지와 썸네일이 새로고침 없이 갱신되는지 확인한다.
- [ ] B의 연결을 끊은 동안 A가 댓글을 등록한다. B를 재연결했을 때 놓친 댓글과 댓글 수가 복구되고 같은 댓글이 중복 표시되지 않는지 확인한다.
- [ ] 모바일에서 첨부, 터치 그리기, 카드 열기를 확인한다. 등록 실패 시 입력이 유지되고 재시도로 저장할 수 있는지 확인한다.
- [ ] 실제 Supabase에 연결해 위 시나리오를 검증하고 빌드를 확인한다. 앱 소스, SQL 마이그레이션, `.env.example`, README를 제공한다. README에는 로컬 실행, Supabase 테이블·Storage 설정, 관리자 이미지 교체와 두 세션 검증 절차를 적는다.
