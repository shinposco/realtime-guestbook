# 실시간 전자 방명록 설계

이 문서는 구현 기준을 정의한다. 현재 구현과 검증 상태는 [progress.md](progress.md)에 기록한다.

## 기술 구성과 화면

- Next.js 14 App Router, TypeScript, Tailwind CSS로 한국어 반응형 UI를 구성한다.
- Supabase Postgres는 방명록과 댓글, Storage는 사진과 손그림, Realtime은 브라우저 간 변경 알림을 담당한다.
- `/`에서 사진 한 장 또는 손그림을 선택해 등록한다. 이미지는 필수이며 빈 캔버스는 등록할 수 없다. 닉네임이 비면 `익명`으로 표시하고 메시지는 선택이다. 사진 미리보기와 마우스·터치 캔버스, 색상, 지우개, 실행 취소를 제공한다. 캔버스 결과는 PNG로 내보낸다.
- `/board`는 최신순으로 정렬한 파스텔색 포스트잇에 썸네일, 메시지, 닉네임, 댓글 수를 표시한다. 모바일에서 카드가 겹치지 않으며 작성 화면으로 돌아가는 버튼을 제공한다.
- 포스트잇을 클릭하면 보드 위에 상세 창을 열어 큰 이미지, 메시지, 작성자, 작성 시각과 시간순 댓글을 표시한다. 인증을 마친 회원은 닉네임과 댓글을 입력해 등록할 수 있다.

## 데이터와 권한

`lib/guestbook.ts`는 공개 키로 Supabase의 방명록과 댓글을 조회하고, 등록 요청을 `moa-write` Edge Function에 보낸다. 이 함수는 Supabase가 제공하는 서버 권한으로 쓰기를 수행한다. 보드에는 최신 글 100개를 표시하고, 상세 창은 선택한 글의 댓글을 페이지 단위로 조회한다. 기존 IndexedDB 미리보기 데이터는 자동으로 이전하지 않는다. 닉네임은 24자, 메시지는 160자, 댓글은 300자, 이미지는 JPG·PNG·WebP 5 MB까지 허용한다.

| 테이블 | 필드 | 제약과 조회 기준 |
| --- | --- | --- |
| `entries` | `id`, `nickname`, `message`, `image_path`, `image_type`, `created_at` | UUID 기본 키, 이미지 경로와 종류 필수, `image_type`은 `photo` 또는 `drawing`, `created_at`과 `id`로 최신순 정렬 |
| `comments` | `id`, `entry_id`, `nickname`, `body`, `created_at` | UUID 기본 키, `entry_id`는 `entries.id` 외래 키, 비어 있지 않은 본문 필수, `entry_id`와 작성 시각으로 조회 |

- 두 테이블에 RLS를 활성화하고 공개 조회를 허용한다. 등록은 인증된 요청을 받은 서버 경로에서 처리한다. 공개 Supabase 역할은 DB와 `moa-artwork`에 직접 쓸 수 없다. 등록 요청과 관리자 이미지 교체의 권한을 구분한다.
- 공개 보드에 사용하는 이미지 버킷은 공개 읽기를 허용하고 쓰기는 서버 또는 운영자에게만 허용한다. DB에는 이미지 URL 대신 객체 경로를 저장한다. 브라우저에는 Supabase 공개 키만 노출한다.
- 서버에서는 이미지의 실제 형식과 크기, 닉네임·메시지·댓글 길이, 빈 댓글 여부를 검증한다. Storage에 허용 형식과 크기 제한을 두고, DB에도 텍스트 제약을 둔다. 구체적인 제한값은 구현 시 결정해 UI와 서버에 일관되게 적용한다.

## 이미지 등록과 교체

서버는 입력을 검증한 뒤 요청 UUID와 이미지 해시로 만든 경로에 파일을 올리고 `entries` 행을 등록한다. 두 작업이 성공한 뒤에만 `/board`로 이동하고 요청 ID로 새 카드를 강조한다. 재시도에서는 동일 ID와 경로를 재사용하며 중복 글과 댓글을 만들지 않는다. 저장 결과가 불명확한 경우 동시 요청에서 참조할 수 있으므로 파일을 보존한다. 실패 시 작성 화면은 사진 또는 그림과 텍스트를 유지한다.

이미지를 교체할 때 운영자는 새 Storage 경로에 파일을 올리고 `entries.image_path`를 갱신한다. 이미지 종류가 바뀌면 `image_type`도 갱신한다. 첫 버전에서는 관리자 테스트로 이 동작을 확인한다.

## 실시간 동기화

- `entries`와 `comments`를 `supabase_realtime` publication에 추가한다. 보드는 `entries`의 `INSERT`로 카드를 추가하고 `UPDATE`로 표시를 갱신한다. 상세 창은 보드의 선택된 행을 참조해 이미지가 바뀌면 썸네일과 큰 이미지에 같은 변경을 반영한다.
- 보드는 `comments`의 `INSERT`를 받아 해당 글의 서버 댓글 수를 갱신한다. 상세 창은 현재 `entry_id`의 `INSERT`만 받아 댓글을 갱신한다. 상세 창을 닫거나 다른 글로 바꾸면 이전 상세 구독을 해제한다. 보드를 벗어나면 보드 구독도 해제한다.
- 보드 진입, 상세 열기, 실시간 연결 복구 시 최신 데이터를 조회한다. 실시간 이벤트와 등록 성공 응답은 새 조회를 시작하는 신호로 쓰고, 화면은 중복을 포함하지 않는 조회 결과로 교체한다. 요청 순번을 확인해 늦게 도착한 응답이 최신 상태를 덮어쓰지 않도록 한다.

## 인증·인가

저장소의 `moa-write`는 Supabase Auth에서 이메일 인증을 마친 회원의 글·댓글만 등록한다. 보드·상세·이미지 조회는 방문자에게 공개한다. 호스팅 환경에 적용한 내역은 [progress.md](progress.md)에 기록한다.

| 동작 | 방문자 | 이메일 인증을 마친 회원 | 운영자 |
| --- | --- | --- | --- |
| 보드·상세·이미지 조회 및 실시간 갱신 | 가능 | 가능 | 가능 |
| 방명록·댓글 등록 | 로그인 필요 | `moa-write`로 가능 | 회원으로 등록할 때 동일 기준 |
| 기존 이미지 교체 | 불가 | 불가 | 권한이 부여된 운영 환경에서 가능 |

- 회원은 이메일·비밀번호로 가입 및 로그인하고, 가입 확인 메일을 재요청할 수 있다. `/auth/confirm`은 Supabase 기본 메일의 세션 전달과 앱 템플릿의 토큰 해시를 모두 처리한다. 기본 메일이 Site URL로 돌아오면 앱의 확인 화면으로 이동한다. 비밀번호 변경에는 링크에서 확인한 계정의 임시 세션을 사용한다. 브라우저에서 로그인 세션을 유지·갱신한다. 작성 화면과 상세 창 안에서 로그인할 수 있어 세션 만료 후에도 열어 둔 화면의 입력을 보존한다.
- `moa-write`는 사용자 액세스 토큰을 먼저 검증한다. 인증된 계정 ID는 Auth 응답에서 가져온다. 화면의 닉네임은 기존과 같이 표시용이며 비워 두면 `익명`으로 표시한다. 계정 ID와 이메일은 보드, 이미지 경로, 실시간 이벤트에 노출하지 않는다. [Edge Functions 인증](https://supabase.com/docs/guides/functions/auth)
- 공개 테이블과 Realtime publication을 유지한다. 계정 연결과 요청 지문은 Data API에 노출하지 않는 스키마의 `entry_ownership`, `comment_ownership`에 둔다. 각 행은 원본 글·댓글 ID를 기본 키 겸 외래 키로, `author_id`를 `auth.users.id` 외래 키로 갖는다. 원본 삭제 시 연결 행을 정리하고, 계정 삭제 시 `author_id`를 `NULL`로 바꿔 게시물을 보존한다. 전환 전 글·댓글에는 연결 행을 만들지 않는다. [Supabase 스키마 노출 기준](https://supabase.com/docs/guides/database/tables)
- `anon`·`authenticated`의 DB·Storage 직접 쓰기를 차단한다. 등록 RPC는 공개 행과 작성자 연결 행을 한 트랜잭션에서 저장한다. 같은 계정의 동일 입력만 성공으로 재응답한다. 운영자는 기존 권한으로 이미지를 교체할 수 있다. 회원 수정·삭제와 운영자 화면은 이번 구현 범위에서 제외한다.
